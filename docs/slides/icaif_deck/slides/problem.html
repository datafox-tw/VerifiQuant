The problem

A number is not an answer

The dangerous failure is a confident, well-formatted, wrong number. Nothing marks it as wrong.

Program-aided reasoning fixes the arithmetic

The model writes code and an interpreter runs it. The numbers come out reliable.

It does not decide if a number is legitimate

A question can be out of scope, miss an input, hold an impossible value, or leave a convention open. A program that runs returns a clean number anyway.

LLMs in finance now sit in workflows that end in a number: valuation memos, portfolio analytics, client calculators, regulatory reports. They rarely fail by crashing. They fail with a clean, wrong number. PAL-style reasoning makes the arithmetic reliable because an interpreter runs the code. But reliable arithmetic does not make the answer legitimate. That gap is what this work is about.
