When a user picks a non-default convention, say payments at the start of each period, the computation must change. If we let the LLM rewrite the code, we reopen the door the funnel just closed. So every edit is declared on the contract at build time. For the loan it is an output transform: divide by one plus the monthly rate. Its invariant: multiply the new payment back and you recover the old one. The payment moves from 1,498.88 to 1,491.42. Three checks: bounded at 13 AST nodes, safe names only, and the invariant holds numerically on five sampled bindings. If asked about code patches: in a proof of concept, a one-node patch for NPV timing (start=1 to start=0) is accepted only if its output matches the declared relation. The library itself uses output transforms.
