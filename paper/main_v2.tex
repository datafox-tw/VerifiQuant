\begin{abstract}
Large language models embedded in financial workflows fail most dangerously by emitting confident, well-formatted, wrong numbers with no signal distinguishing them from correct ones.
We argue that the central deployment problem is therefore \emph{governability}: a system must determine when a question supports a numeric answer and when it should instead clarify, intercept, or refuse.
We present \textbf{VerifiQuant}, a governance-by-execution framework that packages financial logic into inference contracts and evaluates each query through an executable diagnostic funnel before deterministic computation.
This separation makes computation, clarification, and refusal structured and auditable while keeping financial arithmetic outside the language model.
Against matched retrieval-and-execution baselines, our results show that the principal benefit is not higher accuracy on well-posed questions, but safer behavior when an input does not justify a number.
Coverage sweeps and failure analysis further expose the cost and limits of this guarantee: the safety is bought with coverage rather than with accuracy, and residual failures remain attributable to specific runtime frontiers.
\end{abstract}

\section{Introduction}
Financial institutions are deploying large language models (LLMs) in workflows that end in numbers: valuation memos, portfolio analytics, client calculators, regulatory reports. In our trap study, one such workflow is asked to price an option with a Heston stochastic-volatility model. A strong program-writing baseline instead computes an unrelated manufacturing ratio from the surrounding context. The program parses, executes, and returns a clean number, and nothing in the output marks it as wrong.
That failure is not an arithmetic error, and no amount of additional accuracy prevents it. Benchmark accuracy has climbed, and it is tempting to treat the remaining gap as one more model generation away from solved. We argue that framing misses what blocks deployment: a financial workflow fails in production less because it computes the wrong number than because \emph{nobody can govern when it should output a number at all}. A deployable system must also know when \emph{not} to answer, that is, when a question is out of scope, missing required inputs, boundary-violating, or ambiguous in a way that changes the computation. Deterministic execution addresses the arithmetic but not these qualification failures: a syntactically perfect program can compute the wrong financial semantics, force-fit a formula the library does not contain, or answer a question without inputs.
The key question is therefore not whether deterministic execution improves arithmetic, but whether executable controls can stop a system from emitting a number when the query does not justify one. PAL and its successors execute the computation. VerifiQuant executes the decision of whether computing at all is legitimate.

Testing that requires holding everything else fixed. A system with contracts also carries retrieval and deterministic execution, so beating a plain generative baseline would not say which component earned the gain. We therefore build \textbf{R-PAL}, a retrieval-augmented program-aided baseline in the PAL/PoT family: it receives the \emph{same} top-4 retrieved contracts VerifiQuant does, writes a self-contained program, and executes it deterministically, but runs no gates.
On clean questions R-PAL matches or beats autonomous VerifiQuant (\S\ref{sec:v2res}). On inputs that support no legitimate numeric answer, executed governance intercepts what execution alone force-fits. Supplying the same M/N/F/E/I taxonomy to that baseline as prompt text leaves false numeric acceptance at \govPromptFnar{}, whereas executing the checks as contract-bound code brings it to \govVQfnar{}.
Clean-set accuracy is therefore not our contribution. What we contribute is \emph{governed behavior on malformed inputs}. The controls we execute are motivated by recurring model-risk, auditability, and human-oversight requirements for high-stakes AI \cite{fed2011sr117,euaiact2024,finra2020ai}: declare scope boundaries, validate inputs, disclose ambiguity, log reproducibly, and route to human checkpoints where the system cannot resolve a question autonomously.
We do not claim regulatory compliance. We borrow these requirements only to define design targets.

\paragraph{Contributions.}
\emph{First}, \textbf{VerifiQuant} executes scope, schema, boundary, and ambiguity checks as contract-bound code rather than as instructions to a model. To show that the gain comes from executing them, our load-bearing baseline receives the identical M/N/F/E/I taxonomy as prompt text together with the same backbone, retrieval, execution environment, and scoring, so the only remaining difference is whether the checks run, and the \govGap{}-point separation above locates the gain in execution rather than in the taxonomy itself. The same design delimits the claim: on clean, well-posed questions the baselines match or beat autonomous VerifiQuant, so clean accuracy is not what we contribute.

\emph{Second}, we give a mechanism that makes those checks executable. Financial Inference Contracts combine applicability conditions, typed inputs, deterministic computation, numerical invariants, and declared semantic ambiguities, and an executable diagnostic funnel turns refusal, clarification, and computation into structured, attributable outcomes rather than free-form text.
\emph{Third}, we characterize the boundary and cost of this guarantee through library-coverage sweeps and failure attribution. To address the circularity concern inherent in contract-derived stress tests, we additionally evaluate on 80 naturalistic queries independently labeled by five finance-trained annotators blind to our contracts and systems. VerifiQuant trades out-of-library answer coverage for a contract-grounded verified/unverified boundary, and clarification-assisted results are reported only as an intent-aware upper-bound analysis.

\paragraph{Scope.} Our evaluated territory is the formula-grounded numerical core: a single question whose answer is one number, produced by applying a known financial formula to inputs that appear in the given text, such as pricing a bond from its face value, coupon, maturity, and yield, or computing a present value from a cash-flow schedule and a discount rate.
Multi-document extraction, data freshness, jurisdictional policy, and non-numerical judgment are out of scope.
Throughout, \emph{out-of-library} (OOD) denotes a formula family absent from the contract library \emph{within this benchmark's ontology}.

\section{Problem Formulation and Related Work}\label{sec:v2problem}
We frame the deployment question directly: \emph{given a financial question and context, when is emitting a numeric answer legitimate?}
Each response falls into one of three outcomes: a \textbf{correct} numeric answer, a \textbf{silent wrong} (a confident, unflagged, incorrect number), or a \textbf{structured abstention/clarification} that names why no answer was emitted.
We measure \emph{coverage} (fraction answered), \emph{selective accuracy} (correct among answered), \emph{silent-wrong rate} (SWR, silent wrongs over all items), and, on adversarial inputs, \emph{false numeric acceptance rate} (FNAR).
Silent-wrong rate is the key deployment-risk metric. For every system, informal prose refusals are counted as abstention, not as silent wrong.

In the trap set, no legitimate \emph{unqualified single} numeric answer exists: a required field is missing, a declared boundary is violated, a material convention remains unresolved, or the ask is outside the evaluated task scope.
Any un-intercepted number is therefore a false numeric acceptance by construction, not an ordinary accuracy error: the correct behavior is interception, clarification, or slot-filling, and emitting a confident single number is unsafe.
On the trap set we also report two attribution scores. \emph{Exact diagnostic} (Diag) requires the emitted label to equal the trap's generating class (F, E, I\textsubscript{HARD}/I\textsubscript{SOFT}, or N). \emph{Action} is stricter than merely withholding a number: it also requires the matching grounded response, namely requesting the removed F field, naming the targeted E rule or field, asking a non-numeric I\textsubscript{HARD} clarification or issuing an I\textsubscript{SOFT} warning, or refusing an N request as out of scope.

\paragraph{Executing the computation.}
Several directions address parts of this problem. Program-aided reasoning \cite{gao2023pal,chen2023pot} delegates arithmetic to an interpreter and removes computation error, but it does not qualify the query: a perfectly executing program can still encode the wrong formula, binding, or convention with no signal that it did. Neuro-symbolic methods \cite{pan2023logiclm,olausson2023linc,ye2023satlm} obtain guarantees by translating language into solver input, but the translation step is the dominant error source and specification synthesis is undecidable in general \cite{zhou2026formaljudge}. A direct head-to-head is also structurally awkward, because those pipelines target discrete logical deduction rather than continuous financial arithmetic. VerifiQuant moves formalization offline instead: contracts are built and validated at build time, so runtime only selects and binds within a pre-verified space.

\paragraph{Deciding whether to answer.}
Answer-or-abstain methods \cite{elyaniv2010foundations,geifman2017selective}, and more recently conformal and calibration-based procedures \cite{quach2024conformal,kadavath2022language}, threshold a confidence score and can carry statistical error bounds, but they abstain on a probability rather than on a named cause. A score-based rule also buys little resolution here. Sweeping a self-consistency threshold ($k{=}5$, vote share as the score) over the same 250 clean questions of \S\ref{sec:v2design} moves coverage only from \scCovOpen{} to \scCovTight{} and SWR from \scSWRopen{} to \scSWRtight{}, because \scUnanimous{} of the 250 are already unanimous and the score has little resolution left to spend. At the threshold matching VerifiQuant's $84.0\%$ coverage it holds \scSelAccTight{} selective accuracy against $96.7\%$. That reference point carries no retrieval and is not a conformal procedure. VerifiQuant instead abstains on \emph{contract-declared checks} (scope, schema, boundary, ambiguity), so each exit names which check failed. Model-risk, auditability, and oversight requirements \cite{fed2011sr117,euaiact2024,finra2020ai} motivate these controls but define targets, not a compliance claim, and multi-agent financial systems \cite{kundu2025multiagent} add natural-language consensus in which failures propagate silently across agents \cite{cemri2025mas}.

\section{VerifiQuant}\label{sec:v2method}
\subsection{Financial Inference Contract}
An FIC packages one formula family into four essentials keyed by \texttt{fic\_id}: (i) \emph{applicability and non-applicability} conditions plus retrieval metadata that decide whether the contract applies; (ii) \emph{typed inputs}; (iii) \emph{deterministic compute} code in plain Python; and (iv) \emph{numerical invariants and declared semantic ambiguities} (period timing, percent-versus-decimal, unit basis), each ambiguity carrying resolution options and a hard/soft level.
For concreteness, the \texttt{Loan} card types \texttt{principal}, \texttt{annual\_interest\_rate}, and \texttt{loan\_term\_years}, carries a boundary check that fires when the rate reaches $1.0$, and declares the decimal-versus-percentage reading of that same rate as a hard ambiguity. A rate entered as $6$ is therefore intercepted deterministically, while the same confusion below $1.0$ surfaces as a clarification.
The LLM's role is \emph{mapping into contracts}, that is, selecting, binding, and flagging. It never performs the financial computation.
Contracts are governed at build time: compute code passes execution smoke tests, invariant expressions are lint-gated against the exact runtime evaluation namespace, and a pre-declared output-type policy is enforced by audit.
The 250-card library used here is generated fully automatically (three staged LLM calls per family plus deterministic normalization) and never reads any per-question worked solution or gold answer.

\subsection{Executable diagnostic funnel}
\begin{figure*}[t]
\centering

\Description{A left-to-right funnel routes a question through intent, scope, schema, boundary, ambiguity, and compute stages. Failed checks produce structured exits; successful paths end in a numeric answer with a diagnostic report, with hard ambiguities routed through verified repair.}

Given a question and context, gates fire in order and each produces a \emph{DiagnosticReport} (Figure~\ref{fig:v2pipeline}).
\textbf{M/N} ask whether exactly one applicable contract exists. The exit is a structured disambiguation request or a scope-boundary refusal.
Candidates reach this gate from a purely lexical retriever: SQLite FTS5 BM25 over each card's title, summary, keywords, and embedding text, merged with a keyword-overlap ranking and filtered by the contract's declared selection hints. Nothing in the retriever is trained, tuned, or fitted to the evaluation sets, and the same retriever and top-4 depth serve all three compared systems.
Depth is not the binding constraint at this library size. On the 250 clean questions, where each question's gold contract is in the library by construction, the gold card is retrieved at rank 1 in the median case and appears in the top 4 for $94.8\%$ of questions; widening to 8 adds $2.4$ points and to 16 adds $4.0$. A larger $k$ or a stronger retriever therefore has under five points of headroom on in-library queries, which is why we hold $k{=}4$ fixed rather than tuning it. Dense and hybrid neural retrievers remain untested.
\textbf{F/E} ask whether the inputs are complete and satisfy the contract's deterministic checks. The exit is a slot-filling request or a boundary alert naming the violated check.
\textbf{I} asks whether an unresolved declared ambiguity would change the computation (blocking I\textsubscript{HARD}) or only its interpretation (warning I\textsubscript{SOFT}). The blocking level is contract-declared, so runtime decides only which declared hints a question leaves unresolved.
\textbf{C} performs deterministic execution with an audit log.
Abstention is not a fallback: five funnel conditions can terminate in a structured non-answer exit, while I\textsubscript{SOFT} proceeds with a warning and C computes. Auditability is scoped precisely.
Deterministic execution and invariant evaluation replay exactly from the stored binding. LLM-mediated selection and binding decisions are logged, so a historical decision can be re-executed as recorded. A fresh rerun from raw text, however, is \emph{not} guaranteed to take the identical path.

\subsection{Bounded repair}
When a hard ambiguity changes the required computation, free-form regeneration would reopen the door the funnel just closed.
Repairs therefore use AST-bounded transforms. Before acceptance, the numerical effect must match a contract-declared algebraic relation at the point of use on multiple sampled inputs.
This is bounded numerical validation, not formal equivalence. It catches single-sided errors, but a wrong invariant paired with a compensating patch would pass. We assume a non-adversarial patch generator, not an attacker fitting patches to the sampled bindings.
We audit the 179 synthesizable transform specs in the 250-card library with six generated patch-error classes (Table~\ref{tab:repairbench}). Of 906 mutants, 27 are arithmetically equivalent and excluded. The verifier rejects \textbf{97.7\%} of the remaining 879 mutants; 20 are false accepts (2.3\%), while both structural attacks are rejected at 100\%. These residuals concentrate in conditional transforms whose guard branch the five sampled bindings did not exercise, including 10 identity mutants. This controlled distribution probes verifier mechanisms; it does not estimate the catch rate for LLM-generated patches in the wild.

\section{Experimental Design}\label{sec:v2design}
\subsection{Clean in-library evaluation}
We evaluate on 250 FinanceReasoning \cite{tang2025financereasoning} questions (180 medium, 70 hard) from the function-linked subset in which each question carries a formula-level reference implementation.
The contract library is built from those reference functions. The pipeline never reads the per-question worked solution or numeric gold answer, and it deduplicates formula kernels by AST hashing.
By construction a card therefore contains the formula its matching question needs: the evaluation is \emph{in-library}, and it measures routing, binding, and gating, not unseen-formula derivation.
This is a structural constraint of the only benchmark that ships per-question formula provenance.
The out-of-library analysis of \S\ref{sec:v2res} uses a second, fixed split of the same 250 questions: the library is rebuilt from 50 formula families, which leaves 199 questions whose family is absent (OOD) and 51 whose family is present (ID). The comparison there is matched in the same way as the clean set. Both systems run the same backbone on the same 199 questions with the same question and context, and both retrieve top-4 from the \emph{same} 50-family library, so the baseline is not given a larger library or a different prompt. Because the split is predetermined by formula family rather than difficulty, both systems receive the same unchanged questions and differ only in whether the funnel runs.

\subsection{Matched baselines}
We compare systems on the clean set.
\emph{CoT} is a single-shot generative baseline (the LLM computes).
\emph{PAL} writes Python executed deterministically, with no retrieval and no contracts.
\textbf{R-PAL}, a retrieval-augmented PAL/PoT baseline, is the load-bearing comparison: it receives VerifiQuant's \emph{identical} top-4 contract retrieval as candidate context, then writes a self-contained program executed deterministically.
R-PAL shares VerifiQuant's backbone (Gemini 2.5 Flash), question and context, top-4 retrieval, deterministic execution, and scoring (1\% output-scale-normalized tolerance). The \emph{only} difference is VerifiQuant additionally runs executable governance gates.
Any R-PAL program that fails to parse, raises, times out, or returns ``cannot solve'' is counted as abstention, not silent wrong.
The $1\%$ tolerance is a general-purpose threshold rather than the stricter convention the benchmark applies to its own leaderboard, and one scorer applies it to every system, so it cannot favor any of them. It also does not touch the headline: false numeric acceptance counts whether a system emitted a number on an input that admits none, so the trap results in \S\ref{sec:v2res} are independent of the tolerance entirely.

%% It is deliberately loose enough to absorb unit and scale reporting differences instead of
%% numerical error, and a tighter threshold would move all accuracies together.
%% [/ICAIF-CUT]
\textbf{R-PAL$^{+}$} is identical to R-PAL in backbone, retrieval context, execution environment, and scoring. Its prompt additionally supplies the complete M/N/F/E/I governance taxonomy and requires an explicit execute, refuse, or clarify decision before program generation. It has no executable gates, so it isolates the effect of \emph{describing} the governance controls from the effect of \emph{executing} them.

\subsection{Governance perturbations}
To test qualification directly we derive traps from clean questions and their contracts by deterministic operators: \textbf{F} removes a required input, \textbf{E} injects a value violating a declared E-check, \textbf{I} deletes a declared disambiguator, and \textbf{N} substitutes an out-of-scope ask.
The label \emph{is} the operator, and each E injection is verified to fire the contract's own predicate.
Because traps are contract-derived, this is a \emph{mechanism-targeted stress test}, not an estimate of natural deployment incidence.
The M (under-specified intent) operator does not yield a reliable quantitative trap, because an under-specified question retains metric-bearing context. We hence make no numeric claim for M.
We use a balanced 80-trap confirmatory set (F/E/I/N, 20 each; 52 base questions, $\le$2 operators each).

\subsection{Autonomous vs.\ clarification-assisted operation}
$K{=}1$ (funnel-only, no clarification) is the primary deployable setting.
$K{=}3$ is an idealized recoverability analysis: a constrained oracle may read the question's intent specification (ground-truth computation code) but never the numeric answer, and may only rewrite the question/context.
$K{=}3$ is therefore an upper-bound-style analysis of what clarification could recover, not a production result. All trap evaluation uses $K{=}1$, because an oracle would re-inject redacted values and defuse the traps.

\subsection{Human-labeled external-validity set}\label{sec:v2ext}

\paragraph{Construction and annotation.}
The F/E/I/N traps are contract-derived, so a skeptic can ask whether their labels merely re-encode our own checks (\S\ref{sec:v2design}).
To test the governance boundary against labels defined \emph{independently} of our contracts, we build a second evaluation whose ground truth comes from human domain experts with no access to any system, contract, or gold answer.


An independent GPT-5.2 author rewrites FinanceReasoning topics into 80 naturalistic queries with no access to our contracts, the M/N/F/E/I/C taxonomy, gold answers, or any system output. The author model is deliberately different from the solver stack (Gemini 2.5 Flash, used by every evaluated system), so a question's messiness is uncorrelated with what any solver finds easy. Items are drawn from four latent conditions, well-posed (27), missing a required input (18), ambiguous in a material convention (18), and judgment or out-of-scope (17). The condition is a sampling stratification, never a label, and is hidden from annotators, so the panel's label distribution need not match it. Five finance-trained annotators, blind to the source question, the generating condition, and every system output, independently assign one of four actions with a one-sentence rationale. Majority labels are frozen before any system is scored, all 80 items reach a first-pass majority so no adjudication was needed, and we report Fleiss' $\kappa$ as reliability. Full curation checks, instructions, and worked examples ship with the released audit trail.

\paragraph{Label definitions.}
Annotators assign one of four labels per item by a top-down rule, stopping at the first ``yes'': is the ask itself not ``compute one number'' (advice, a forecast, or a request needing unavailable data)? then \textsc{out-of-scope}. Is a required numeric value missing from the text? then \textsc{request-info}. Are all values present, but would an interpretation choice (percent vs.\ decimal, which period, which metric, day-count basis, gross vs.\ net, per-share vs.\ total) change the number? then \textsc{clarify}. Otherwise, a complete and unambiguous computation is \textsc{answer}.
The \textsc{request-info} versus \textsc{clarify} contrast (a missing number versus an unclear interpretation) is trained explicitly, and the full instructions ship with the audit trail.
Each action maps onto a funnel outcome (\textsc{answer}$\leftrightarrow$compute, \textsc{request-info}$\leftrightarrow$F, \textsc{clarify}$\leftrightarrow$I, \textsc{out-of-scope}$\leftrightarrow$N/M), so emitting a confident number where the human label is \textsc{request-info}, \textsc{clarify}, or \textsc{out-of-scope} is a false numeric acceptance defined by human judgment rather than by our taxonomy.

\paragraph{Ethical considerations.}
The items are synthetic and contain no personal information, and only labels and rationales about each question were collected. Participation was voluntary, annotators are anonymized as \textit{Annotator}~1--5, and consultation with our institution determined that ethics-committee review was not required.

\paragraph{Artifacts.}
We release the 250-card contract library and the staged prompts that build it. The human evaluation ships with its 80 queries and provenance, the five per-annotator label files, the frozen majority ground truth, and the agreement report. Scoring and aggregation scripts come with an audit trail that records the scoring conventions and when labels were frozen relative to each system run.

\subsection{RQ2: On inputs that should not produce a number, does executed governance help?}
This is the headline result (Table~\ref{tab:v2main}, Panel B).
On the F/E/I/N traps, plain R-PAL force-fits a program and accepts a confident number \govPlainFnar{} of the time.
Handing R-PAL the \emph{full} M/N/F/E/I governance taxonomy in its prompt lowers this only to \govPromptFnar{}.
VerifiQuant's executed gates reach \govVQfnar{}, a \govGap{}-point reduction over the taxonomy-prompted baseline (base-question-clustered 95\% CI $[\govCIlo{},\govCIhi{}]$). They also emit the correct structured exit far more often (exact diagnostic \govVQdiag{}, action \govVQaction{}, versus \govPromptDiag{}/\govPromptAction{}).
The panel answers three questions at once: execution is not governance, retrieval access is not governance, and \emph{describing} governance in a prompt is not \emph{executing} it.
Because the traps are contract-derived (\S\ref{sec:v2design}), a declared check fires deterministically once the right contract is selected and its inputs are bound. The non-trivial content of this result is therefore not that a check catches its own violation. It is that selection and binding succeed often enough for the check to apply, and that executing the check outperforms supplying the identical taxonomy as prompt text.
The FNAR advantage concentrates on E and I, where correctness depends on an executable boundary or an unresolved convention rather than on an obviously missing field (Table~\ref{tab:v2trapop}). There, plain R-PAL force-fits almost always, and even the taxonomy-prompted variant stays high, whereas VerifiQuant's executed checks hold.
On F and N the systems are close, and VerifiQuant is in fact marginally \emph{worse} than the taxonomy-prompted baseline (F: $10\%$ vs.\ $0\%$; N: $5\%$ vs.\ $0\%$). A missing field or a blatant out-of-scope ask is conspicuous enough for prompting to refuse. VerifiQuant's few residual acceptances here instead trace to the \emph{binding} frontier: the model fills the absent slot with a plausible nearby value, so the completeness (F) gate sees a satisfied schema, and an out-of-scope ask is occasionally force-fit onto a near-neighbor contract.
These are the selection/binding failures we localize in \S\ref{sec:v2boundary}, not gate omissions.
The per-class columns of Table~\ref{tab:v2trapop} show where each system's exits are actually wrong rather than only how often it emits a number. VerifiQuant is strongest on the operator whose evidence is a missing field (F, exact diagnostic $90\%$) and weakest on the one that requires reading an unstated convention (I, $60\%$). Its I errors are informative: of the twenty I traps, nine are downgraded to a soft warning and four pass as ready, so the residual is a wrong-level or missing trigger inside the ambiguity gate rather than a gap in the contract's declared ambiguities. R-PAL$^{+}$ shows the opposite profile. It labels conspicuous operators almost perfectly (F $100\%$, N $88\%$) while collapsing on I ($10\%$), which is the same asymmetry visible in FNAR and is what a prompt can and cannot enforce.

\paragraph{Safety versus utility.}
Figure~\ref{fig:v2safety} places autonomous operating points on a safety--utility plane. \paragraph{What the funnel costs.}
The same ladder prices the controls, since every rung runs the identical 250 questions on one backbone in one environment (Table~\ref{tab:v2gateladder}).

The cost sits in the ambiguity gate, which introduces a third model call and raises the figure to $12.7$\,s. The full funnel runs at $12.2$\,s against $10.5$\,s for plain R-PAL and $8.2$\,s for R-PAL$^{+}$ on the same set, so executed governance costs roughly $1.2\times$ a retrieval-and-execution baseline and under a third of self-consistency at $K{=}5$ ($38.1$\,s).
These are wall-clock means that include provider-side variance and retries, and we do not report token accounting, so they bound the order of magnitude rather than the marginal cost of a deployment.

\subsection{RQ4: Does an independent human panel corroborate the boundary?}\label{sec:v2rq4}
This is the external-validity check for the contract-derived trap result, with labels defined by human experts rather than by our operators (\S\ref{sec:v2ext}).
We first establish that the human labels are reliable. Agreement across the five experts is almost perfect (Fleiss' $\kappa = 0.84$), and a $\ge 3/5$ majority is reached on all 80 items, so no adjudication is required. The majority splits into 34 \textsc{answer}, 20 \textsc{request-info}, 10 \textsc{clarify}, and 16 \textsc{out-of-scope}, so 46 of the 80 queries call for something other than a plain number. These are the panel's labels, not the sampling conditions of \S\ref{sec:v2ext}. We then score each system by its \emph{human-defined} false numeric acceptance rate, that is, the share of \textsc{request-info}/\textsc{clarify}/\textsc{out-of-scope} queries answered with a confident number, and by action-level agreement with the human majority label (Table~\ref{tab:v2ext}).
VerifiQuant's human-defined FNAR ($8.7\%$) is again the lowest, below R-PAL$^{+}$ ($13.0\%$), CoT ($21.7\%$), and plain R-PAL ($56.5\%$), and among the three systems Panel~B also evaluates the ordering is unchanged. Over the 46 non-\textsc{answer} items these rates are 4, 6, 10, and 26 emitted numbers, so only the separation from plain R-PAL is individually significant (Fisher exact $p<10^{-4}$, against $p{=}.74$ for VerifiQuant versus R-PAL$^{+}$). What RQ4 establishes is therefore not a second powered comparison of the two governed systems, but external validity for the direction: a panel blind to every system, labeling queries our operators never touched, reproduces the Panel~B ordering, so that ordering is not an artifact of our own trap construction.

VerifiQuant's Match ($32.5\%$) and answered count ($11/80$) are correspondingly low, and this reflects retrieval, not caution alone. VerifiQuant answers only 7 of the 34 items the human panel judged answerable ($20.6\%$). In 24 of the 27 shortfalls, top-4 retrieval never surfaces an applicable contract for the paraphrased query (for example, a LIFO-costing question retrieves only a FIFO-costing card), so VerifiQuant correctly declines rather than force-fitting the wrong formula. This is the same selection frontier of \S\ref{sec:v2boundary}, now observed under naturalistic paraphrase rather than contract-derived perturbation. The abstentions are therefore traceable to retrieval coverage rather than spread at random, but on this set that same mechanism also removes most of the utility, so the low human-defined FNAR is bought at a far larger coverage cost than on the clean set. A gold answer derived for all 34 answerable items shows that cost plainly. R-PAL and R-PAL$^{+}$ are correct on every item they answer, and the only item any system misses is a single forward-rate question, missed by both CoT and VerifiQuant. Abstention here therefore buys no accuracy, the same exchange as the out-of-library split.

\paragraph{Scoring protocol.}
Each system's raw output is normalized to an action in $\{$A, R, C, O$\}$, with the full per-system mapping in the released audit trail. Two conventions matter for reading Table~\ref{tab:v2ext}. CoT and plain R-PAL expose only whether they answered, never why they declined, so scoring them four-way would discard credit for correct abstention; their Match is the binary agreement between answering and a human \textsc{answer} label, while R-PAL$^{+}$ and VerifiQuant expose a real R/C/O decision and are scored four-way. An M-refusal is scored \textsc{out-of-scope} per \S\ref{sec:v2ext}, even though every M-refusal here carries an explicit clarification question, which is a conservative reading of our own convention rather than one chosen after seeing the scores: an \textsc{M}$\to$\textsc{clarify} reading would raise VerifiQuant's Match from $32.5\%$ to $35.0\%$. \section{Boundary and Failure Analysis}\label{sec:v2boundary}
\paragraph{Where the claim holds.}
The empirical claim requires three conditions: the target formula family exists in the library; the contract's specification and invariants are sufficiently correct; and the question is formula-grounded deterministic numerical reasoning.
Open-world numerical reasoning and cross-dataset generalization fall outside the scope of this claim.
Where these conditions fail, VerifiQuant provides at most a scope signal, not a correct answer.
The clean-set result is in-library by construction, and out-of-library behavior is exactly the trade-off examined in RQ3.

\paragraph{Where failures remain.}
Every residual silent wrong localizes to one of three predeclared, LLM-mediated \emph{runtime} frontiers: contract \emph{selection} (choosing or force-fitting a near-neighbor contract), input \emph{binding} (extracting or scaling a value wrongly), and \emph{declared-hint recall} (failing to trigger an ambiguity the contract already declares).
Empirically, every residual observed in the 250 clean questions and 80 traps fell into one of these three frontiers. The count depends on the operating mode: the autonomous $K{=}1$ clean truncation has seven silent wrongs (Table~\ref{tab:v2kabl}), whereas the clarification-assisted $K{=}3$ clean run has eight. The latter comprise three selection, two binding, and three declared-hint-recall failures; this eight-case attribution is not used as the $K{=}1$ SWR numerator.
It also marks a clear limit: we do not verify input \emph{provenance}, that is, whether a bound value is drawn from the correct source field. Our checks confirm only that a value satisfies the contract's schema and boundary, not that it was sourced correctly, which is exactly why the binding frontier remains.
Distinct from these are \emph{build-time defects}, such as a contract that omits an ambiguity or encodes a wrong invariant, and, in this library, three indicator cards that returned a series instead of a scalar. These defects are caught before runtime by the contract audits and the pre-declared type-policy check of \S\ref{sec:v2method}, not by the funnel.

\paragraph{Recoverability.}
Clarification recovers part of the abstained mass. Truncating the same $K{=}3$ run (Table~\ref{tab:v2kabl}), VerifiQuant answers autonomously at $81.2\%$ accuracy ($K{=}1$) and, with one or two clarification opportunities, reaches $92.4\%$ at $K{=}2$ and \vqAccAll{} at $K{=}3$, converting abstentions into correct answers while keeping SWR approximately flat and selective accuracy between $96.3\%$ and $96.7\%$ throughout. These turns incur interaction cost, and the oracle sees the intent specification but never the numeric answer. Because the oracle holds that specification, this is an upper bound on clarification benefit, not evidence that an arbitrary user supplies equivalent clarification, and we report it as an idealized analysis.

\paragraph{Remaining limitations.}
VerifiQuant reduces and localizes silent wrongs but does not eliminate them, and residual attribution uses gold answers unavailable in deployment.
Our results also rest on a single formula-provenance benchmark and a single backbone family, so cross-benchmark and cross-model generality remains untested; extending the funnel to other backbones is future work.
Beyond the self-consistency reference point of \S\ref{sec:v2problem}, a retrieval-matched selective baseline and a calibrated conformal procedure both remain untested.
% The governance advantage is measured on a mechanism-targeted, contract-derived trap set that may favor a contract-gated system. In addition, the I\textsubscript{HARD} stratum is small, open-ended intent (M) is unsolved, and results rest on one formula-provenance benchmark and backbone family.
To address the circularity concern, we corroborate the trap advantage on an independently labeled human messy-query set whose ground truth is set by domain experts blind to every system (\S\ref{sec:v2ext}, RQ4). VerifiQuant's advantage holds on human-defined FNAR, though its low answered count on that set is a retrieval-coverage cost, not evidence against the boundary claim.

\section{Conclusion}

% On well-posed in-library questions, a matched retrieval-execution baseline already suffices. The value of executed governance appears elsewhere: on inputs that should not produce a number, where it reduces false numeric acceptance beyond what execution or prompted governance achieve, and on the verified/unverified boundary it maintains when its library ends.
% When a gate identifies that the computation cannot be verified, VerifiQuant emits a structured refusal or clarification rather than an unsupported number. Whether that exchange is worth making is a property of the deployment rather than of the method: it pays wherever an unflagged wrong number costs more than a declined one, as in valuation, regulatory reporting, and client-facing calculation, and it does not pay where coverage is the binding constraint.
For formula-grounded financial workflows, model accuracy alone is insufficient: deployment also requires governing when a numeric answer is justified. VerifiQuant compiles scope, schema, boundary, and ambiguity checks into an executable funnel that makes refusal, clarification, and repair attributable outcomes. Its value emerges not on well-posed in-library questions, where matched execution already suffices, but on inputs that should not yield a number and at the library boundary. It is worthwhile when an unsupported number is costlier than abstention, but less so when coverage is the primary constraint.
