# 11/06 進度：harness PoC 第二輪

上一輪（10/31）的結論是：自動卡片沒有失去好約束，但只有一半的題目答得出來。
這一輪做了三件事：讓卡片支援「衍生量」、把四捨五入交給 harness、第一次跑 80 題陷阱題。
每個版本都跑 3 次，用逐題翻轉判斷改動是否真的有效。

## 一句話

**乾淨題的正確輸出從 27/50 提高到平均 33/50（66%），輸出但錯仍只有 1 題，而且是標準答案錯。
陷阱題的 FNAR 是 27.1%，比論文的 VQ（10.4%）差，和 prompted R-PAL（27.5%）相近。**
自動卡片擅長驗證「程式算得對不對」，不擅長判斷「輸入合不合理」與「題目有沒有說清楚」。

## 1. 乾淨題 50 題（三次執行）

| 版本 | 改了什麼 | 正確輸出（三次） | 平均 | 三次結果相同 |
|---|---|---|---|---|
| v2（10/31） | 候選拿到欄位定義與輸出單位 | 27、27（兩次） | 27.0 | 44/50 |
| v3 | 衍生量卡片 | 33、31、29 | 31.0 | 45/50 |
| v4 | v3 + 程式自行四捨五入視為 bug | 34、32、33 | **33.0（66%）** | **47/50** |
| 論文 VQ（公式卡，含模擬使用者多輪） | | 48 | | |
| CoT 單次（論文） | | 37（另有 9 題輸出但錯） | | |

輸出但錯在每個版本、每次執行都只有 test-1490，人工確認是標準答案錯（3.35% 加 25bp 應為 3.60%）。
v4 第一次執行有 35 題輸出，34 題正確，唯一錯的就是這題。

### 衍生量卡片怎麼做

上一輪 6 題結構性拒答，原因全都一樣：函式庫回傳的是清單或字典（攤還表、移動平均序列、肯特納通道），
harness 卻只收單一數字。這一輪的作法是：

1. **卡片宣告輸出結構**：由 LLM 讀函式庫函式，描述回傳值的層次（第幾期、哪個欄位、哪個部門），
   不變量完全沒動，仍是上一輪那一批。
2. **題目用選取路徑取值**：意圖步驟除了欄位，還要給一條路徑（例如 `result[0]["interest_paid"]`）和原文出處。
   路徑的每一層都由程式確定性地檢查：「sixth year」只能對到第 6 年那一格，「Sales」必須出現在引用文字裡。
   故意給錯的位置（把 sixth year 填成 index 6）會被拒絕。
3. **元素探針**：把題目要的那一格改動 0.1%，若沒有任何不變量發現，就拒答。
   這是為了防止「卡片管住整張表的形狀，卻沒管住題目問的那一格」。肯特納通道的卡片正是如此
   （只有上軌 ≥ 中軌 這類不等式），探針攔下了它。

結果：7 題結構輸出題中，4 題三次都答對（移動平均、定存階梯、費用分攤、迴歸斜率），
3 題仍拒答：卡片的不變量本身有錯（攤還表）、檢查員誤讀欄位意義（歸屬排程）、探針攔下（肯特納）。

### 四捨五入閘

v3 剩下的翻轉，多半是某份候選程式在內部四捨五入（5.29 對 5.2914），和其他候選分歧後只好拒答。
v4 把「程式呼叫 round()」直接當成 bug 淘汰，四捨五入交給輸出端。平均多 2 題，三次結果相同的題目從 45 升到 47。
剩下 3 題翻轉都在檢查員。

## 2. 陷阱題 80 題（三次執行，第一次跑）

FNAR = 陷阱題仍給出數字的比例，越低越好。評分直接呼叫論文的 `score_traps`，harness 單次執行、不回答追問
（陷阱題用的是 v3 設定，沒開四捨五入閘；這不影響「給不給數字」）。

| 系統 | FNAR（三次） | F 缺欄位 | E 輸入不合理 | I 歧義 | N 超出範圍 | 不含 I_SOFT |
|---|---|---|---|---|---|---|
| harness | **27.1%**（25.0、27.5、28.7） | 0% | 30–35% | 55–60% | 15–20% | 19.2% |
| VQ（論文，top-4 三次平均） | 10.4% | 10% | 8% | 22% | 2% | 8.1% |
| R-PAL prompted（論文，三次平均） | 27.5% | 0% | 30% | 80% | 0% | — |
| R-PAL plain（論文） | 48.8% | 10% | 90% | 95% | 0% | — |

拿掉 I_SOFT（harness 沒有警告模式，對它不公平）之後差距仍在：19.2% 對 8.1%。
所以這不是計分方式造成的，是 harness 真的有攔不住的類型。

### 陷阱題沒攔住的原因

- **F（缺欄位）攔得最好**：缺什麼就問什麼，和 VQ 一樣。這是「每個數值要有原文出處」直接帶來的。
- **E（輸入不合理）**：自動卡片的前置條件只寫型別與正負，沒有「加工時間 1500 萬小時不合理」這類常識。
  VQ 的卡片有專門的合理性規則，自動卡片沒有。
- **I（歧義）**：兩個來源。
  - I_SOFT（只拿掉「以百分比表示」這類措辭）：harness 沒有「附警告照做」的模式，輸出了就算錯。這 9 題的數字其實都對。
  - I_HARD（拿掉 call/put）：卡片若把 call/put 做成有預設值的參數，harness 會沿用預設值而不問；
    另有一題陷阱題本身不夠歧義（原文仍寫著「買入股票的選擇權」，等於 call）。
- **N（超出範圍）**：題目換成「用 PDE 解美式選擇權」這類問題，但情境段落沒換。
  選卡與意圖步驟看著情境段落，以為還是原題，就照原題算了。

## 3. 需要你（我）決定的事

1. **I_SOFT 怎麼算**：harness 沒有「附警告照做」。照論文規則全算 FNAR，還是另外報一個不含 I_SOFT 的數字？
   建議兩個都報，主表照論文規則。
2. **陷阱題要不要變成開發集**：上面每個原因都有明確修法（有預設值的類別參數改成追問、意圖步驟只看最後的問句、
   卡片生成加合理性前置條件）。但照陷阱題改完再用陷阱題評，數字會偏樂觀。
   選項：(a) 先不改，這一版就是預先登記的結果；(b) 改，另做一份新的陷阱題當測試集。
3. **卡片可不可以拿參考函式自我檢查**：產生卡片時，把參考函式在隨機輸入上跑一次，刪掉它自己都通不過的不變量。
   這會修掉 3 張壞卡，但 G3 的 Complete 會變成必然 100%，失去評估意義。這算不算洩題，要和老師確認。
4. **候選程式能不能看到不變量**：現在候選只拿到欄位與輸出定義，看不到不變量（獨立性較好）。
   給它看，邊界行為的失敗大概會少很多，但驗證就變成「照著考卷寫答案」。
5. **四捨五入閘要不要設為預設**：v4 比 v3 好，但它也會擋掉合理的 `round()`（例如把月數取整）。目前是開關。
6. **展示網站要不要重新部署**：Cloud Run 上的版本是 10/30 的，之後 harness 改了不少（6 個展示例子的結果不變）。
   部署是對外動作，要你點頭。
7. **commit**：harness_demo/ 整個資料夾還沒進 git。要 commit 到 camera-ready-experiments，還是開新分支？
