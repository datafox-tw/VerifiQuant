# PoC 結果摘要（2026-10-31）

設計見 [../POC_PLAN.md](../POC_PLAN.md)。逐題數字見 `runs/full/REPORT.md`（第一輪）與
`runs/full_v2/REPORT.md`（第二輪，候選程式多拿到欄位定義與輸出單位）。

## 一句話

**自動產生的卡片沒有失去好約束（G3 大致及格），輸出的答案也幾乎都對（G2 及格），
但只有一半的題目走得到輸出（G1 不及格）。** 卡住的地方主要不是卡片強度，而是卡片的「形狀」：
一張卡只算一個數字、輸入的定義傳不到寫程式的模型、四捨五入造成分歧。

## 設定

- 50 題：從論文 250 題依難度分層抽樣（medium 36、hard 14），43 個主題，跑之前就凍結題號。
- 卡片：Gemini 2.5 Flash 讀函式庫函式產生，看不到題目與答案；稽核刪掉會洩題的不變量。
- 選卡：在全部 250 張卡中做全文檢索取前 8 張，再由 Gemini 選一張。
- harness 單次執行，不回答追問；VQ 是論文的公式卡加模擬使用者多輪，條件不同，僅供參考。

## 回答老師的兩個問題

**會不會失去好的約束？大致不會。** 自動卡平均 10 條不變量，84% 同時有 base case 和遞迴或關係式，
錯誤變異中位數全部被抓到。稽核刪掉 41 條（31 條語法錯、5 條用了不存在的名稱、5 條直接寫出公式）。
弱點有兩個：四捨五入到兩位小數的變異有 7 張卡抓不到（base case 多半落在整數點，看不出四捨五入），
另有 3 張卡含錯的不變量，會誤殺正確程式。

**泛用性？目前不夠。** 卡住的 22 題拆開來看：

| 原因 | 題數 | 性質 |
|---|---|---|
| 題目問的不是卡片的輸出（攤還表的第幾期、移動平均的第二個值、迴歸的斜率） | 6–7 | 結構限制：一張卡只定義一個數字 |
| 卡片的不變量有錯或數值上做不到（遞迴式寫錯、到期日趨近 0 的 base case） | 3 | 卡片品質 |
| 程式讀輸入的方式和卡片不同（題目的「漲幅」是 0.4，卡片當成 1.4） | 2 | 規格沒傳到；第二輪補上欄位定義後仍未解 |
| 候選程式自行四捨五入，造成無法區分的分歧 | 3 | 程式生成的紀律問題 |
| 檢查員算錯或照抄錯的公式 | 2 | 檢查員本身有雜訊 |
| 選錯卡，被不變量擋下 | 2 | **這是安全機制正常運作** |
| 結構化輸入的出處比對失敗而追問 | 3 | 出處比對太嚴格 |

## 必須一起報告的限制

- **一次執行無法比較版本。** 兩輪總數完全相同，但有 6/50 題（12%）在兩輪之間翻轉。
  第二輪的修正是否有效，要多跑幾次才能判斷。
- **歧義機制幾乎沒被測到。** 50 張卡只有 2 張定義了約定；乾淨題也本來就少歧義。
  「先排除 bug 再追問」的核心主張要用陷阱題（論文的 80 題）測。
- 9 張卡無法評分（參考函式回傳多個值或抽不出輸入）；變異程式是通用的 6 類，不是領域專屬。
- 洩題稽核是近似的：例如把某個輸入改成 0.000001、其他維持原值，幾乎等於在原點重算，稽核攔不到。
- 為了讓 harness 能處理英文題，這次改了 harness 本身：程式不准自行四捨五入、
  判斷「答案一致」的容差放寬到 1e-5、檢查員當機時重試一次、沒有不變量的卡直接拒答。
  這些都是通用修正，展示網站的 6 個例子結果不變。

## 建議的下一步（依影響排序）

1. **卡片支援「衍生量」**：允許卡片宣告多個輸出（攤還表的每一期、迴歸的斜率與截距），
   對應 6–7 題結構性拒答。
2. **四捨五入交給 harness**：候選程式若有 `round(` 就退回重寫，或在比對前統一精度。
3. **陷阱題 80 題**：才測得到追問與「bug 或歧義」的區分。
4. **每個版本跑 3 次**，用逐題翻轉率判斷修正是否真的有效。
